# Phase 2.1 research — 30 September 2026

## Owning contracts

NAP-RELAY PR 2 remains open, head `0be8abce18beb46ca37bd4ddd042f58d30b4eedc`. Its query request is `{type:"relay.query",id,filters:[...]}` and successful reply wraps raw signed events as `{type:"relay.query.result",id,events:[{event}]}`. On failure the owning prose allows `error` instead of `events`. The SDK 0.27.2 and injected Kehto bridge both expose query. The existing selection of this exact draft is retained.

NIP-01 checked at `0046368a747c5c25ae2bec28bae0e537744c8f10`: filters OR together, conditions within each filter AND together; ids/authors/#e/#p require exact lowercase hex64, timestamps are inclusive, limit zero excludes stored events, ties order by ascending id. Unknown extended filters are outside this selected core profile and fail explicitly.

## Integration

Runtime main currently overrides relay.publish only. The ordinary native lease lane already carries bounded requests to the shared capability broker; query belongs there, not in the signing approval lane. The Android/iOS app-only WSS owners accept bounded REQ filters, terminate at matching EOSE and enforce destination/DNS/TLS/lifecycle limits. Their socket limits are 32 events and 64 frames per relay. New query validation stays separate from kind-35129 manifest discovery.

Native broker validity must be checked before network dispatch and after every result. Broker revocation aborts its queries; a synchronous native lease check also guards app-background expiry even before RN lifecycle delivery. Global query limits and per-session limits prevent an untrusted guest exhausting sockets.

## Selected bounded query profile

At most four filters, 64 members per filter list, 16KiB request, core ids/authors/kinds/since/until/limit and single-letter tags only. At most 32 unique signed events, 64KiB per event, 512KiB aggregate event bytes, a 15-second total deadline and two concurrent queries globally. Each query visits configured Network relays sequentially; at least one complete valid EOSE response is required. Individual relay failures may be tolerated if another succeeds; this is best-effort retrieval, not proof of complete history. All failure or malformed responses cannot become empty success. Sidecars omitted. No cache.

## Validation Architecture

Contract tests: true signed fixtures, filter matching, empty vs failure, forged signatures, stale cached-verification flags, duplicates, bounds, timeout/cancellation and partial failure. Broker tests: exact correlation, native owner/grant denial, concurrency, revocation before dispatch and while in flight. Genuine SDK fixture browser tests exercise reply shapes and untrusted text. Native builds and visible Android/iOS journeys then prove host delivery; physical-device and verified-published evidence remains separate.
