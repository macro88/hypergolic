# Execution research — source-led readiness

Read the current roadmap, requirements, architecture, development commands, fixture documentation, tester build script and transferred Outbox register. Existing owning-contract revisions remain pinned in each accepted capability document; Phase2.11 verifies their implementation together rather than selecting new contracts.

- scripts/build-tester.mjs requires an existing readable keystore outside the checkout, pinned Node/pnpm, ARM64 native output, exact Release permissions, alignment and a signing certificate. --check is read-only and currently fails because HYPERGOLIC_KEYSTORE_PATH is unset. Do not generate a replacement key or pretend unsigned compilation is an installable tester build.
- docs/development.md provides ordinary Android export/prebuild/Gradle and generic unsigned iPhoneOS Release compilation. app.json selects org.nostrocket.hypergolic.dev, version0.0.0/versionCode1 and disables Expo updates. The normal root index.ts registers src/App.tsx. No test ENTRY_FILE override belongs in the final product.
- Native iOS identity-store availability excludes Simulator. devicectl lists only simulated iPhones and security find-identity reports0 valid identities. Unsigned iPhoneOS compilation is independent work; provisioning and device runtime stay open.
- All seven MVP fixture groups exist: UX, State, Approval, Feed, Resource, Upload and Routing. Routing requires distinct target instances/published artifacts. Current per-fixture scripts provide type-check/build/browser/conformance checks. Conformance skips are explicit and cannot close SDK/native rows.
- tests/native/live-update-publication/release-pair.mjs and the per-capability staging helpers sign disposable local artifacts; they are not proof of publishing the designated release key's current fixture bytes. Keep release-preparation, public publication and app-generated disposable events separate.
- The original requirements matrix and eleven OB rows enumerate acceptance ownership. Full physical cross-capability work must include keyboard/Back/accessibility/motion, clean/dirty/unknown close, order/drafts/scroll, persisted explicit-empty, identity/import/backup/delete, update/grants/isolation, malicious guest boundaries, network and provider uncertainty.

Exact machine-local inventory and builds belong in canonical Notes. No anonymous benchmark, packaging log, mock port or disconnected UI/core pass substitutes for complete current product evidence.
