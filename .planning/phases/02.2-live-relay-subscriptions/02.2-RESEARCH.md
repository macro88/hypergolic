# Phase 2.2 research — 30 September 2026

Selected owning NAP-RELAY draft remains `0be8abce18beb46ca37bd4ddd042f58d30b4eedc`;
its full source was fetched again. NIP-01 remains the phase-2.1 revision
`0046368a747c5c25ae2bec28bae0e537744c8f10`.

Public wire: subscribe has `id`, caller-owned `subId`, filter array and optional
`relay`; close has `id`/`subId`. Event has `subId`/`result:{event}`, EOSE has
`subId`, terminal closed has `subId` and optional `reason`. There is no
`relay.subscribe.result` or `relay.close.result`. A background socket pause is
not a terminal closed message. Repeated EOSE after reconnect describes refreshed
stored history, not a gap-free guarantee. No sidecars or encrypted-event
processing is selected; unsupported encrypted surfaces must remain explicit.

The current native client consumes one `.result` per transport sequence and
expires at 27 seconds; native ordinary leases expire at 25 seconds. Reusing this
lane for persistent events would fail correlation and revoke otherwise live
streams. A distinct native stream admission/delivery lane must capture the same
immutable registration, use the shared sequence replay boundary, remain bounded
and retain its native generation guard. WKScriptMessageHandlerWithReply replies
once: persistent pushes need a separately captured main-actor delivery function,
not repeated calls to the promise reply handler. Android reply proxies can push,
but must apply equivalent generation/foreground checks.

Native WSS currently completes at matching EOSE with a ten-second deadline and
lifetime frame/result budgets. Live reads need a separate streaming owner with
bounded queued frames/bytes, rolling rate limits, acknowledgement/backpressure,
TLS/public-DNS policy reuse and immediate socket cancellation on background.
Do not weaken or repurpose published discovery/query behavior.

Implementation profile: two logical subscriptions/session, eight/process, up to
two trusted Network relays/subscription. A scoped relay must already belong to
the trusted Network snapshot; arbitrary guest destinations remain denied.
Core filters reuse query validation. Event validation stays fresh hash/signature
and filter matching. Dedupe retains the latest 1,024 IDs; replay beyond that
window is best effort. Reconnects repeat bounded recent-history filters, retry
at 1/2/4/8/16 seconds and terminate after exhausted attempts when no relay remains.
Native queues must bound four unacknowledged frames and 256 KiB per connection;
relay floods fail closed. Explicit close/owner revocation removes intent and
invalidates callbacks before stopping sockets. Focus switching has no teardown.
Background retains logical intent and rendered guest/drafts while sockets close;
foreground creates new connection identities and refreshes/deduplicates.

The current published host deliberately fails on background. Retaining it for
this approved lifecycle requires narrow read-session suspension while preserving
signing cancellation, transfer revocation and renderer/navigation fail-closed
behavior. Its old physical/published acceptance gaps remain final phase 2.11.

Execution is inline GSD fallback; no typed researcher/planner/checker claim.
