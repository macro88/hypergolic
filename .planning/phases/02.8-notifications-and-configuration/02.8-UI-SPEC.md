# Trusted shell UI

Reuse existing trusted Settings/review palette and native control conventions. Notification requester title/publisher and selected identity are shell-sourced; guest text is labelled content, never treated as markup or authority. Bound text and rows; use text labels rather than fetched guest icons. Permission sheet: exact channel and requester, Allow notifications / Not now. Settings lists remembered scopes with revoke action. Centre uses source-attributed bounded cards, up to3 actions, body click and dismiss; low priority remains centre-only. Background clears cards and badges.

Config Settings shows verified source/version, grouped ordered schema fields, plain descriptions/deprecation notes, masked secret inputs with explicit set/clear, and separate commit button. Never show persisted secret text or place it into JSON editor. Nested objects/arrays may use validated JSON controls; display validation feedback after save/interaction, preserve drafts on failure, announce accessible errors. No napplet-rendered settings. Runtime openSettings is focused/rate bounded.
