# Phase 2.3 context

The product interview completed on 30 September 2026. Continue the authorized build, preserving the existing branch and source location, and pause at 50% weekly usage consumed. Source push/remotes remain owner-controlled.

Confirmed decisions:

- Enable bounded HTTPS, SHA-256-verified Blossom, one-hop Nostr and embedded data resources.
- Cache only in memory while the napplet remains loaded. Switching retains cached content; restart requires refetch. Bind cache ownership to saved identity, publisher, app, aggregate revision and native renderer generation.
- A resource grant permits any public HTTPS domain without per-file prompts. Private/local destinations remain blocked after DNS and before connection.
- Provide a small editable default Blossom download-server list in trusted Settings. Research actual hosts; this does not select an upload provider.
- Include bounded audio/video playback alongside images and attachments. Pause when switching or backgrounding, retain position while loaded and resume only after Play.
- Close, identity change, replacement and renderer termination revoke old work, handles and cache authority.
- Revisit Hashtree and safe SVG rasterization after Phase 4. Reject raw SVG in this profile. Streaming and large-file delivery remain distinct unresolved work; do not assign them a delivery phase implicitly.
- State the basis, tradeoffs and assumptions behind recommendations. Unmeasured effort does not establish a blocker.

Engineering choices remain within these decisions: exact draft pin, tested byte/queue/rate/format limits, private bounded byte carrier, cancellation handling, provider validation and declared one-hop Nostr representation. The draft's recommended 10 MiB limit is a candidate, not a product prohibition on larger future files. Do not claim full resource-domain conformance or native acceptance before proof.

Installed GSD runs inline under its Codex spawn-restriction fallback; typed planner/checker guarantees do not apply.
