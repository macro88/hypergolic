# Resource validation strategy

CAP-04 remains open. Native Android/iOS proof and actual media behavior are required.

1. Contract: strict exact fields, unknown schemes, correlated result/error, no cancel reply, ordered mixed bulk results, genuine Blob projection and SDK abort handling.
2. Boundary: sender/generation/native lease, public/mixed/private DNS, TLS identity, bounded public redirects, redirect loop/private/downgrade/hop denial and compression denial, oversized Content-Length/chunk/eof, malformed framing, timeout and cancellation.
3. Integrity: expected bytes/hash and sniffed MIME despite lying headers, Blossom mismatch/fallback, no raw SVG/HTML, one-hop validated Nostr without destination hints gaining authority.
4. Lifetime: equal IDs in separate sessions, cache LRU/budget and identity/revision isolation, close/replacement/background/renderer cancellation, revoked private transfers and object URLs.
5. Native journey: real SDK retrieves and displays image plus plays audio/video on Android and iOS; actual switching/background pauses, return requires Play, cold restart refetches. Capture source/build/fixture hashes, screenshots and playback/time evidence.
6. Regressions and release: existing runtime/capability/query/subscription/published/identity/storage/security checks, exports/prebuilds and both Release compiles; full numeric quality and all lockfile audits; public diff/privacy review and coherent commit.

Fast existing commands: `pnpm run typecheck`, `pnpm run test:capabilities`, `pnpm run runtime:test`, `pnpm run test:query`, `pnpm run test:subscriptions`. Resource test scripts and native drivers must be implemented before using planned invocations; skipped and simulated cases are never reported as observed native acceptance.
