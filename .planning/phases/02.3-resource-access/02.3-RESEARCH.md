## Native boundary

The packaged runtime/native ordinary JSON channel is capped at 2 MiB and 25-second native leases. Keep that gate. A final 10 MiB file cannot fit in one Base64 reply; implement bounded private byte transfer with captured-generation ownership, fixed-size chunks, exact length/hash, expiry, one-use claims, process quotas and synchronous native revocation. Public SDK receives one complete Blob, never internal handles/chunks. Begin with a real small-image tracer through the same final ownership path.

Reviewed public DNS/pinned-TLS/framing helpers already exist in PublishedHttpsTransport.java and PublishedPinnedHTTPS.swift. Preserve the published-loader profile and tests. Resource fetch requires resource-native lease ownership, typed failures and cancellation before and after work, rather than exposing the trusted published-loader bridge. Resource redirects are limited to two HTTPS hops under the original native deadline. Every target undergoes credential/scheme/host checks, fresh public-only DNS validation and pinned TLS; loops and private/mixed targets fail closed. The published loader continues to reject redirects. This revises the initial zero-hop candidate after actual Primal hash retrieval returned HTTP 302 to its public storage host. Neither Location nor upstream Content-Type reaches the guest. Bound compressed/framed/raw bytes before allocation; reject compression rather than decompress unbounded data.

Initial target limits: 10 MiB per file, 8 URLs per bulk, bounded aggregate successful bulk bytes, 2 fetches/session and 4/process, 60 URL requests/minute/session, 30 MiB session cache and 50 MiB process cache with exact-URL LRU eviction. Declare a separate monotonic delivered-byte budget because the SDK retains Blobs and host code cannot reliably observe guest GC. Reject unknown active formats, HTML/XML and raw SVG; sniff supported raster, audio/video containers, bounded UTF-8 text/JSON and passive attachments. These are engineering targets to adjust based on measured native proof, not accepted conformance yet.

## Scheme and provider choices

HTTPS is credential-free public native GET. Blossom accepts the selected NAP's `blossom:sha256:<hex>` form, checks the SHA-256 after every server attempt, and uses only the shell server configuration. BUD-10 has different URI hints; do not silently add that surface. Candidate defaults are `https://blossom.primal.net` and `https://cdn.satellite.earth`, named in the owning Blossom URI examples. Verify public hash retrieval and pin the owning BUD-01 revision before acceptance; no reliability claim follows from examples.

Nostr resolves through trusted relay configuration and existing signature/hash/filter validation, with caller hints unable to add destinations. The resource draft leaves its byte representation underspecified. Select and document a narrow event-reference representation after inspecting proposal discussion and implementations; no recursive network follow or private decryption. Unknown forms fail explicitly.

## Playback and verification

Permit only Blob-based audio/video sources when resource access is granted, keeping direct guest network denied. Native visibility/background changes must pause the captured guest's media before stale lifecycle callbacks can act. Returning cannot auto-resume; user-initiated play is rechecked. Preserve position only for the retained loaded realm. This does not add the separate NAP-MEDIA domain, OS media controls or background-audio services.

Both native platforms must render known images and actually play known small audio/video through the genuine SDK and native transport. Codec/container coverage is tested, not assumed. Verify pause across switching/background, explicit return Play, object-URL release and old-realm revocation. Distinguish controlled HTTP fixtures, actual native network journeys and transport doubles. Preserve physical-device and final-published MVP gaps. Quality acceptance requires full React Doctor/aislop 100/100 and all lockfile audits clean on the final source seal.


## Resolved technical research

Blossom BUD-01 retrieval is pinned to owning repository revision `b5bd2801d1763aa635fc8fea7a76597e0eb18990` (inspected 30 September 2026). The NAP proposal's ordinary/review comments do not specify Nostr byte representation. Select a narrow explicit compatibility profile: note/nevent/naddr references return UTF-8 JSON for one strictly verified public signed event, using trusted configured relays and no recursive follow; keys/profiles, encrypted events and unsupported forms fail explicitly. This representation is a declared host interpretation, not an assertion that the owning draft mandates JSON. NIP-19/NIP-01 remain pinned to `0046368a747c5c25ae2bec28bae0e537744c8f10`.

Keep a request's total native work below its 25-second ordinary lease: target a 20-second total resource request deadline, including bulk/fallback work, and a 15-second URL deadline. Recheck lifetime while native work runs and before every private byte transfer. SDK timeouts are not the native authority. Internal chunk pulls are host-only, captured-generation operations; guest request validation must reject private transfer fields and verbs.
