SDK0.27.2 / nap0.31.2 and runtime nap0.31.1 expose identical Outbox wire files. Domain outbox requires relay; resource is optional. Operations are getEvent, query, subscribe, close, publish, resolveRelays. There is no outbox.eose. Query/getEvent preserve RelayEventResult and partial/incomplete semantics. Subscribe pushes outbox.event and outbox.closed; limit applies to initial backfill. Resolve direction read selects author write relays; write selects recipient read relays. Plans use source nip65/cache/policy/fallback with missingAuthors where applicable.

Publish uses unsigned template and deduplicated own-outbox/defaulttrue, explicit toInboxes and explicit relays union. The pinned draft limits each outbox.publish request to at most one signed event, including already signed events. D-06 selects a profile extension: review and separately redistribute an existing signed kind10002 alongside the one newly signed primary event. This extension is not strict conformance to that draft limit. Resolve every required policy-allowed recipient relay before review/signing; missing required inboxes fail. Signing-first reference service behavior is unsuitable. Trusted UI distinguishes accepted/rejected/unknown separately from the wire receipt representation. Common draft errors include not found, no authors, relay list unavailable, relay timeout, policy denied, publish denied, invalid filter.

NIP65 kind10002 r tags select read/write; omitted marker means both. NIP01 newest replaceable wins; ties lowest id. Invalid/private URL tags cannot grant native transport authority. NIP65 broader p-tag SHOULD routing differs from selected explicit NAP recipients; document this intentional selected-profile deviation. Existing signed relay-list redistribution must be visible, approved and independently receipted.

## Reuse and integration

Read src/network/relay-query-contract.ts for fresh hash/signature/filter bounds, relay-settings.ts for public WSS, native-relay-query.ts and native-published-relay.ts for app-only transport, identity/identity-cache.ts for leased SQLite pattern. New cache needs author keys and finite quota, not unbounded reuse of guest StringStorage. Existing native source/lease/DNS policy must protect discovery and dynamically resolved destinations. Do not expose shell transport configuration through guest props.

Read runtime/src/main.ts and native-client.ts, runtime-owner and existing subscription broker/native transports before wire integration. Existing injected relay config is empty and legacy pool disabled; activating browser pool is not a native Outbox implementation. Use genuine SDK fixture in Feed Lab or a dedicated Outbox fixture through the ordinary attested host path.

## Validation Architecture

Node built-in tests run under pinned local Node with strip-types. Wave0 adds `test:outbox` and native drivers; currently no native Outbox acceptance. Use signed real events for tamper, replacement, role and cache tests. Native Android/iOS original SDK tracer must precede stream/publication expansion. Retain sealed source/package/product hashes, request/results, native logs, screenshots and input/AX evidence; build success is packaging evidence only.

Threats: untrusted URL expansion, forged/cache-mutated lists, stale identity/source, required-relay truncation, changed targets after approval, hidden ancillary publication and unknown ACK presented as rejection/success. Each has a negative assertion in the phase validation contract. Static quality, existing capability/security tests and ordinary exports/packages remain required before final acceptance.
