Wire: link.open {id,url,options?:{label?:string}}; link.open.result {id,status:'opened'|'denied',error?:string}. Every correlatable request needs a result. Relative/local/code-bearing URLs are forbidden. Label is an untrusted hint. The shell selects the target and prompting policy. Opened records accepted handoff, not successful loading. No opener or bytes are returned.

Installed SDK0.27.2 and NAP/core0.31.1 already expose this surface; SDK resolves both statuses and omits optional wire error from its public result. Kehto shell0.20 supports link advertisement and concrete service registration. Use a source-bound service with captured recipient and native client, preserving ACL/domain/firewall gates; no new operation override is required if registered service routing works. Verify this through the genuine SDK rather than infer behavior from exports.

Native ordinary leases revoke on background. A native-owned link review and one-shot handoff receipt need a separate bounded state machine: background before dispatch denies; background caused by an accepted dispatch cannot falsely report failure or authorize another action. Close/replacement/user change still ends ownership. UIKit completion can arrive after resign-active; Android startActivity accepts before main-loop lifecycle callbacks. Verify actual delivery and return before accepting this design.

Primary platform references: https://reactnative.dev/docs/linking ; https://developer.android.com/training/app-links/create-deeplinks ; https://developer.apple.com/documentation/uikit/uiapplication/open(_:options:completionhandler:). Normal HTTPS opening can select an associated app. Avoid claiming forced browser, page success or handler support from a package export/canOpenURL check. No extra package dependency or broad app enumeration is justified.

Modern web guidance security search/retrieval applied: preserve CSP/sandbox, source-bound postMessage and text-only rendering. Do not weaken navigation or network restrictions to implement link.open.

Implementation seams: CapabilityConfiguration/CapabilityTransport; Android NappletHostView.receiveCapability; iOS RestrictedNappletHost.receiveCapability; runtime main.makeHooks and validEnvelope; native-client recipient/deadline checks; bundled catalogue, manifests, publication capability compatibility. Native host review avoids exposing opening authority as guest props or a generic app API.
