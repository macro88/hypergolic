## Cache and permission architecture

Use a dedicated trusted SQLite database for bounded signed source-event bundles and app-scoped sensitive-list grants. Avoid changing guest storage or silently upgrading old domain grants. Reuse storage/connection.ts for serialized transactional native-active checks, and schema.ts configure for durability. Cache keys capture public user plus a fixed selected read key. Reverify signatures and ownership on reads; never trust serialized derived results. Freshness is five minutes. After a bounded refresh failure, serve an existing older validated bundle under D-03, without inventing a freshness wire extension. A successful absence is a cacheable verified observation; no-cache offline is an error. Newer cache events must not be overwritten by older responses; NIP01 tie breaks use lowest lexical ID. Retain empty newer lists rather than resurrect older content. Revoke permission independently of data caching and recheck it before delivery.

Permission review names user, verified publisher/app and the sensitive public data. Persist only a live approved decision. Denial does not grant permission; Settings can revoke the remembered allowance. Review, storage, query and delivery must end on native lifetime revocation. Bound requests, reviews, rows, event sizes and joins; reject oversize/incomplete results rather than truncate silently. Existing trusted Network/Lookup settings remain network authority; discovered NIP65 and relay hints never add destinations.

## Threat model

T-01: wrong user, poisoned cache or mutated signed events — revalidate exact signatures/filter/owner and strict stored bundles.
T-02: cached social data bypasses consent — app-scoped current permission checked before reads and delivery, including offline.
T-03: late consent/network/storage replies — immutable native registration, bounded abort watches and final native finish denial.
T-04: unsolicited/forged badges — user acceptance plus exact issuer, recipient, award and definition binding.
T-05: network destination injection — use existing trusted relay configuration only; URL text and hints grant no fetch authority.
T-06: resource floods/cache poisoning/downgrades — declared finite quotas, exact schema, transaction/readback and newest-event selection.
