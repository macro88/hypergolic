## Dependency and scope audit

Six sequential waves because each new behavior uses the previous native/session/identity/signing/resolver layer; this respects source configuration parallelization false. Research/independent checker work can remain parallel without code ownership overlap.

Every plan has three tasks and starts with an end-to-end tracer. Calibration query returned factor1, no samples, confidence low. Coupled module/fixture/lockfile tasks exceed five-file guideline; this is explicitly surfaced rather than hidden or reduced. Executors may split those task commits as needed without changing requirement scope.

Remaining input gates are explicit: signed release publication needs the project publisher/signer/destinations after artifacts are prepared; final phone tests need connected authorized hardware. Neither blocks the first embedded native trace. No source remote/push action is allowed.

Dirty-status protocol is not invented: unknown is guarded; full clean/dirty reporting acceptance stays open if no interoperable owning contract can be selected and verified. This is a real engineering dependency, not permission to discard the behavior.

All proposed commands whose files are absent in the scaffold have an owning creation task. No verification is claimed executed by planning.
